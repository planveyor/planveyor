# Code Reviews

Сюда кладём reviewer artifacts для любого bundle, который не ограничен `docs/**`.

Это именно:
- findings по конкретному `dev`-plan или explicit non-doc bundle;
- rerun verdict'ы по тому же review artifact;
- финальный reviewer/arch-review receipt для текущего slice.

Практический lifecycle для plan-flow:
- `PLAN_PATH` может заранее ссылаться на будущий `docs/code_reviews/<plan_basename>.md`;
- до первого reviewer pass такой файл может ещё не существовать, и это само по себе не считается сломанным handoff;
- pre-Reviewer `planveyor_plan_bundle --preflight` может показывать planned review artifact как `PLANNED`; это только Planner-time handoff proof. Первый live reviewer pass всё равно обязан materialize-ить файл, а после этого `planveyor_plan_bundle --check` должен проходить без `MISSING-PATH`;
- Reviewer до diff использует `planveyor_plan_bundle --scope-check <PLAN_PATH>`: один JSON `planveyor_plan_bundle_scope.v1`, rc0 iff `scope_ok=true`, только exact inventory/integrity. Planned absence и materialized red/stale output остаются completion debt; `not_selected` не validated. Historical support проверяется по path/bytes/hash, selected support независимо по raw validator; producer mismatch допустим только как completion debt после integrity. Никаких green/route/commit permissions; final lint и strict `--check` обязательны после review.
- owner этого файла = Reviewer: именно reviewer materialize-ит первый live artifact и дальше переписывает тот же файл in place по мере rerun'ов;
- если reviewer attempt завершился без chat output / wrapper receipt и declared `docs/code_reviews/...` всё ещё отсутствует, это incomplete attempt, а не зелёный reviewer pass: rerun должен materialize-ить тот же planned path и только потом двигать status;
- missing first-pass artifact path перестаёт быть допустимым сразу после reviewer materialization: первый live pass обязан создать declared review file, чтобы closeout и rerun не зависели от thread memory;
- same-contract rerun переписывает тот же artifact path новым `**Date:**` / `**Target:**` / `**Status:**`; предыдущий blocker/verdict остаётся внутри файла только как `historical anchor` / `stale-only`, а не как молча-current state;
- plan-side `Stale note` / `Rerun note` в `## Review artifacts` = только временный quarantine на время rerun. После same-file rewrite live truth снова живёт в header/body самого `docs/code_reviews/...`; quarantine note не заменяет новый verdict и не должен переживать truthful reviewer closeout как единственный current signal;
- machine route `stale_red_after_fix -> reviewer_same_file_rewrite_required` означает только operational handoff: repo-backed fixed evidence есть, но live red artifact ещё не переписан. До same-file rewrite это остаётся blocking route (`bundle_ok=false`, `commit_ready=false`, `terminal_ready_state=blocked`), а не зелёный verdict;
- если тот же artifact уже переписан и содержит более свежий open blocker после selected fixed-risk evidence, это current blocker/Coder route (`current-review-red` / `review_blocker_requires_resolution`), а не `stale_red_after_fix`; same-minute / lower-precision timestamp ordering считается ambiguous и тоже fail-closed к current blocker;
- если narrow rerun после reviewer/arch-review меняет сам explicit bundle внутри shared target file (например, вычищает piggyback-hunks другого slice), предыдущий verdict автоматически становится stale для current tree: reviewer обязан переписать тот же artifact path заново и literal-но закрыть уже narrowed bundle, а не опираться на старый verdict как будто scope не менялся;
- если early plan/code draft по ошибке materialize-или `docs/doc_reviews/...`, а final bundle к live reviewer pass уже включает non-doc carrier, reviewer в первом live pass обязан перевести `## Review artifacts` и связанные literal refs на `docs/code_reviews/...`; mixed bundle не закрывается через stale docs-only host;
- если final bundle оказывается docs-only, canonical review route = `docs/doc_reviews/...`; `docs/code_reviews/...` не используем “по привычке” только потому, что plan materialized раньше;
- docs-only leftover over a closed non-doc baseline: accepted `docs/code_reviews/...` остаётся `historical anchor only`, а single live reviewer path обязан жить в `docs/doc_reviews/...`;
- review-only / merge-range receipt в этом каталоге остаётся triage companion для конкретного reviewer pass, а не скрытым dev handoff или заменой post-merge audit.

Proof / evidence contract:
- Гигиена Russian-first: новые review artifacts пишем с русской первой summary-строкой (`ОК:` / `Замечания:` / `Вердикт:`). Literal schema labels вроде `Findings:` внутри lane sections допустимы, но prose/values вокруг них должны быть по-русски; `Findings: none` как единственный current verdict не считается Russian-first receipt.
- `**Target:**` держим literal (`COMMIT=current|staged`, `BUNDLE=current|staged`, `PLAN=...`, для merge-range `RANGE=<base>..<head> (EXCLUDE_DOCS=<0|1>)`) по факту handoff;
- Для final merge-range artifacts top-level `**Target:**` и `**Spec:**` являются machine carriers, а не prose: `**Spec:** docs/plans/...md` обязателен для generated/origin-plan reviews; единственный no-origin escape hatch — exact `N/A (origin_plan_state=manual_range_review_no_origin_plan)` для manual range review. Даже в этом режиме `**Target:**` должен literal-но держать requested `RANGE=<base>..<head>`; no-origin invalid when `--origin-plan` is supplied. Human summary, filename, Manager memory и queue state не заменяют эти строки.
- если exact bundle уже semantic-closeout'ed (`already_materialized`, clean worktree, later unrelated edits успели затронуть overlapping shared paths), reviewer не маскирует это под `COMMIT=current`: live verdict должен literal-но ссылаться на historical bounded target (`RANGE=<base>..<head>` или другой exact historical anchor) и коротко объяснять, почему current tree больше не truth surface для этого slice;
- manager-fed docs-closeout fields `final_docs_commit=required|no_op|landed` относятся только к финальному docs-only commit/handoff после memory-finalize family. Они не меняют reviewer target, не переоткрывают terminal plan status и не являются поводом переписывать уже закрытый review artifact; durable lesson из такого запуска поднимаем в canon / `docs/followups/*` / `docs/process_improvements/*`;
- если reviewer blocker касается manager-fed docs-closeout context (`latest_stop_reason_scope`, `historical_stop_reason`, `final_docs_commit` и т.п.), closure proof должен проверять именно docs-closeout output surfaces: `runtime_context`, `dispatch_context_block` и `process_improvement_seed`. Upstream queue/readback (`planveyor_q_show --json`) сам по себе не закрывает такой blocker, пока тот же review artifact не переписан in place с новым verdict;
- если `planveyor_plan_bundle --check` падает не на missing first-pass review artifact, а на malformed/non-canonical linked code draft carrier (`Missing valid code_draft_meta JSON`, empty `code_draft_meta.targets`, invalid target entries, ad-hoc `{"targets": [...]}` без top-level `code_draft_meta`), это exact-bundle blocker / plan-materialization gap: reviewer не угадывает target set по prose и не переводит проблему в code defect; plan возвращается на Planner, а same-file rerun закрывает тот же review artifact path после metadata restamp;
- если truthful closeout зависит от helper/proof lane, exact launcher и support files должны быть declared в plan/README до reviewer pass; отсутствующий helper = reviewability gap / scope question, а не повод для ad-hoc reviewer automation;
- если helper/proof lane валидирует structured markdown carrier перед mutation, read/write surfaces должны быть одним bounded carrier: scoped heading/block или structured parser object. Scoped read + global regex replacement after that = S1 source-of-truth gap; proof должен включать fail-before-mutation render/preflight и regression с non-source row вне carrier;
- screenshot-backed refs должны указывать на literal repo paths under `docs/code_reviews/assets/...`; implicit basename-only refs и “смотри рядом” не считаются exact-bundle-safe;
- если visual lane truthfully не требуется, это пишется в review artifact буквально как `N/A (why)`, а не закрывается молчаливым пропуском.
- Если reviewer materialize-ит новые untracked helper/test/review files, `git diff --check` по tracked paths не проверяет их содержимое; перед `✅ OK` нужен explicit hygiene carrier для новых файлов (`rg -n "[[:blank:]]$" ...`, merge-marker `rg`, или staging-aware exact-bundle check), иначе whitespace/merge-marker proof не покрывает весь bundle.

## Dual-model reviewer contract

- Один live review artifact остаётся единственным host'ом даже для dual-model code review: внутри него literal-но живут `## reviewer_code_risk - GPT-6.1 Sol ultra`, `## reviewer_code_contracts - GPT-6.1 Sol ultra`, optional `reviewer_visual`, `## Lane synthesis / aggregate verdict` и canonical `## S1 Blocker` / `## S2 Risk` / `## S3 Nit`.
- Cross-lane handoff не живёт в Manager memory: сначала `reviewer_code_risk` materialize-ит plan-resident lane-run artifact в `PLAN_PATH` evidence, а `reviewer_code_contracts` читает этот же carrier и валидирует `target_snapshot` перед записью финального review-file.
- `reviewer_code_contracts` finalizer не является relay для risk-lane prose: если risk lane не materialize-ил live review artifact или явно ограничился `plan_evidence_only`, finalizer сам пишет/переписывает `docs/code_reviews/...`, сверяет `target_snapshot`, и фиксирует собственные proof/readback commands либо literal reused-evidence decision с причиной.
- Current enforcement boundary: checked-in lint/helper family machine-check'ит intra-artifact dual-lane schema, final-status gate, and `target_snapshot` parity with the plan-resident `reviewer_code_risk` lane. Для final merge-range artifacts origin берётся из top-level `**Spec:**`; `--origin-plan PLAN_PATH` остаётся parity guard and must match `**Spec:**`. Legacy non-range artifacts may still use `--origin-plan` or one `PLAN=docs/plans/...` in `**Target:**`.
- Support payload optional только когда compact carrier не объявляет ни `full_payload_ref`, ни `full_payload_sha256`. При одном поле пара обязательна: все declared current и historical pairs становятся source-plan exact-bundle members по repo-relative symlink-free (leaf и ancestor) ref/SHA. Historical red/legacy carrier проверяется только на durable bytes; `review_artifact_lint.py --origin-plan` остаётся selected-current-only JSON/schema/parity validator и fail closed на его missing file/hash mismatch/invalid JSON/stale current marker или несовпадение `run_id`, `lane_id`, `target_snapshot`, `lane_status`, `findings`. Incomplete/unsafe/symlink/missing/mismatched/conflicting pair блокирует bundle/closeout до mutation.
- Если review artifact дальше feed'ит `post_merge_audit`, `## Lane synthesis / aggregate verdict` должен literal-но materialize-ить provenance carrier set `source_lane`, `lane_finding_id`, `synthesis_disposition`, `canonical_ref`, `audit_status`, `followup_plan`; при отсутствии findings оставь no-finding placeholder с теми же field names вместо prose-only `N/A`, чтобы audit не восстанавливал их из Manager chat memory или ad-hoc prose.
- Raw lane ids (`risk:R<N>`, `contracts:C<N>`, `visual:V<N>`) остаются локальными для секций lane; canonical blocker refs `B<N>` появляются только после `Lane synthesis / aggregate verdict`.
- Non-draft header status (`✅ OK` / `❌ S1 blocker(ы)`) невалиден без обеих code lanes и literal synthesis.

Это не замена `docs/reviews/`:
- `docs/code_reviews/` = plan-scoped reviewer artifacts для non-doc bundle;
- `docs/reviews/` = durable research / post-merge audit / range summary bucket;
- plan-scoped review artifacts внутри `docs/code_reviews/*` не являются source of truth; сам bucket README остаётся каноном каталога. Если после cleanup нужен устойчивый pointer на findings/verdict, факт поднимаем в canon, `docs/reviews/*` или `docs/followups/*`.
