## Problem
1. Начало explicit-bundle review требует `planveyor_plan_bundle --check`, но тот же helper требует законченный green review. Проверка входного scope зависит от собственного будущего результата Reviewer.
2. `--preflight` допускает absent planned first review, но materialized draft/red/stale review попадает в общий отказ. Это также мешает genuine Planner refinement после materialized review при unconditional preflight-pass wording.
3. Exact inventory и durable support integrity должны оставаться обязательными раньше review. Их нельзя ослабить вместе с completion proof: ранний current-proof return сегодня может предшествовать selected-support validation.
4. По постановке координатора старый Э4а S1 остановился до Coder и реального G7; S2/reentry не запускались. Это контекст проблемы, а не выполненная проверка этого source-fix.

## Как я понял задачу
- Нужно разорвать зависимость начала и повторения review от уже завершённого green review, сохранив строгую проверку входного exact scope.
- Координатор уже выбрал один read-only `--scope-check` в существующем `planveyor_plan_bundle`; новый resolver, prose-parser, wrapper или роль не нужны.
- Режим независимо проверяет selector и selected support, сохраняет historical path/bytes/hash obligations и отделяет completion debt от scope failure; `scope_ok` не разрешает handoff, green review или commit.
- Reviewer получает проверяемый inventory до diff; первый Planner handoff сохраняет strict `--preflight`, а genuine refinement с materialized review получает узкий inventory-only caller contract без обхода остальных gates.

## Solution (high level)
### Выбранное направление и lifecycle решения
`decision lifecycle`: intake/v3/validation contract приняты координатором; Architect материализует native N-A admission и проверяет handoff Planner. `canonical writable owner`: semantic contract — Architect в этом plan; executable resolver — существующий `scripts/planveyor.zsh` через Coder после native handoff. `downstream carrier`: Planner-owned same-stem code draft, derived N-A decision ref и exact targets, затем native Risk+Contracts review/CENSOR. Согласование intake, prompt, test, review и `scope_ok` не становятся runtime enforcement сами по себе.

Один новый read-only mode использует существующий resolver. Входные membership/integrity ошибки блокируют scope; незавершённый Reviewer output остаётся completion diagnostics. Existing strict modes и canonical proof readers сохраняют прежние полномочия.

## Decisions (final)
### Native machine-authority applicability
Выбран `not_applicable / no_machine_authority_change`: новый transient JSON описывает exact input inventory и completion debt, но не создаёт authoritative carrier для автоматического допуска, маршрутизации, записи или закрытия работы. `scope_ok` и rc0 разрешают только считать inventory целым; они не меняют status/queue/refs и не заменяют independent semantic lint, Oracle, selected support, finished review или strict final closeout. Writer diagnostics — существующий resolver; consumers получают производные facts от прежних authoritative inputs. Если реализация потребует permission fields либо иной machine authority, это выход за этот contract: STOP Architect до расширения scope, а не автоматическое сохранение N-A. Required/frozen Owner confirmation и новые authority identities этим N-A не фабрикуются.

### Зафиксированный typed scope/output contract
1. `--scope-check` — новый read-only режим существующего `planveyor_plan_bundle`. Никакого второго resolver, parsing human `reason`, fallback runtime или новой роли.
2. Сохраняются shared resolver guards для canonical `code_draft_meta`, membership, missing/deleted/outside-root paths, explicit assets и durable receipt tracking. Только declared missing planned review допускается как отсутствующий будущий output, аналогично preflight; missing input так не допускается.
3. `collect_plan_risk_lane_support_refs` выполняется независимо от current selection. Все его diagnostics блокируют scope, все его records остаются exact members. Historical collector проверяет существующие path/bytes/hash obligations; schema/parity каждого historical payload ему не приписываются.
4. `select_plan_risk_lane_snapshot` вызывается независимо от раннего current-proof return. Любой `error_code`, включая ambiguity и contradictory lifecycle, — scope failure. При no error и обоих absent `snapshot`/`payload` состояние явно `not_selected`, а не validated. Несогласованная форма selection блокируется.
5. Для usable selected lane независимо вызывается существующий `preflight_selected_risk_lane_support`; используется его raw tuple и рассматриваются все diagnostics. Подмена через `review_artifact_lint._risk_lane_selection_payload` запрещена. Единственное stale исключение selected-support — `current_review_proof_producer_mismatch` после integrity; оно остаётся completion debt. Все остальные и неизвестные diagnostics блокируют scope, включая `current_review_proof_producer_or_support_unavailable` и `current_review_proof_projection_mismatch` из этого validator.
6. `preflight_current_review_proof` остаётся completion readback. Его ранний return не отменяет independent selector/raw selected-support validation. Существующая unconditional ветка `state=blocked -> errors` в `scripts/planveyor.zsh:13454-13457` получает исключение только в scope-only mode, только для точного proof allowlist ниже и только после независимых selector/support проверок. Для old modes ветка сохраняется. `current_review_proof_projection_mismatch` от proof входит в output-debt allowlist; тот же code от support validator — scope failure. Источник diagnostics сохраняется явно.
7. Proof transport/shape failure, unknown state/code, blocked proof без `reason_code`, plan/review outside-root или unreadable, ambiguous review route и `current_review_proof_input_changed` — scope failures. Existing structural/path/machine-authority guards сохраняются; их ошибки можно сообщать verbatim, но нельзя разбирать prose для исключения. `needs_reviewer_rerun` и неразобранный reason string не являются allowlist.
8. Classifier states `current_red`, `needs_reviewer_rerun`, `stale_red_after_fix` сохраняются как completion diagnostics без добавления их closeout problems в scope errors. Это не глобальное исключение для blocked proof: в той отдельной ветке действуют только шесть typed codes ниже. Independent selector/support failure блокирует scope даже при allowlisted proof reason. Open blockers и malformed/duplicate output headers никогда не становятся green или разрешением менять роль.
9. CLI, JSON-only schema/fields и exit contract уже выбраны координатором и зафиксированы ниже; Planner материализует этот contract, а не выбирает serializer заново. `rc=0` означает только `scope_ok`; поля `route`, `next_owner`, `green`, `commit_ready` и admission permission запрещены рекурсивно, включая вложенные projections.
10. Strict N-A candidate использует только inspect-only missing-child allowance существующих print/preflight; materialized parent сохраняет child checks. Rejected-baseline delegated final branches/receipts не меняются. Incompatible flags отклоняются до побочных эффектов.
11. Existing `--preflight`, `--check`, `--print`, mutation/final/closeout modes, их exit/output contracts, Oracle, current-proof reader, same-file classifier и semantic fingerprint status window не меняются. Семантический lint и derived `plan_handoff_digest` не получают bypass.

### Точный allowlist output debt по источнику
Только следующие `reason_code` от `preflight_current_review_proof` допускают scope-only исключение из blocked-proof errors после independent input validation:
- `current_review_proof_target_ambiguous`
- `current_review_proof_target_invalid`
- `missing_plan_resident_risk_lane`
- `current_review_proof_compact_snapshot_invalid`
- `current_review_proof_projection_mismatch`
- `current_review_proof_producer_mismatch`

Raw selected-support tuple имеет отдельный allowlist из одного code: `current_review_proof_producer_mismatch` после integrity. Все entries рассматриваются; отсутствие diagnostics у no-selected не означает validated. Неизвестные/отсутствующие proof codes и все прочие selected-support diagnostics блокируют scope. Parse human `message`/`reason`, alias/prefix matching и второй payload parser запрещены.

### Фиксированный CLI / JSON-only contract v3
Команда: `planveyor_plan_bundle --scope-check <PLAN_PATH>`. Новых companion flags нет. Recovery, docs-closeout, preflight-file и commit-message options отклоняются в этом режиме до side effects; default и existing modes прежние.

После выполнения ordinary resolver stdout содержит ровно один JSON document: `rc=0` тогда и только тогда, когда `scope_ok=true`; обычный scope failure даёт `rc=1`. Existing prerequisite/parser/transport failures остаются nonzero и могут завершить команду до JSON; их отсутствие JSON не превращается в success.

| Обязательное поле | Точный выбранный contract |
| --- | --- |
| `schema` | literal `planveyor_plan_bundle_scope.v1` |
| `plan` | тот же canonical plan display, что в существующем resolver |
| `scope_ok` | boolean, только результат inventory/integrity |
| `errors` | existing resolver errors и явно source-attributed typed failure descriptions; никакой классификации по prose |
| `path_problems` | прежняя shape path → problem-list из closeout inventory, исключая только completion problems этого режима |
| `repo_roots` | ordered list: `repo_root`, exact sorted `bundle_paths`, `path_problems`; без commit skeleton/staged permission |
| `support.historical` | `state` принимает `validated` или `invalid`; все existing collector diagnostics сохраняются. `validated` означает только прежний path/bytes/hash contract |
| `support.selected` | `state` принимает `not_selected`, `validated`, `stale_producer` или `invalid`; selector `error_code`/`message` при наличии и все raw selected-support diagnostics сохраняются. `not_selected` явно unvalidated; `validated` означает только applicable contract существующего selected-lane validator |
| `completion.current_review_proof` | только `{state,reason_code,message,diagnostics}`, с сохранением typed источника |

`support` и `completion` — обязательные top-level objects с перечисленными вложенными projections. Aggregate route, `next_owner`, `green`, `commit_ready` и admission permission запрещены рекурсивно во всём JSON, а не только на верхнем уровне.

### Выбранная caller policy
- Reviewer pre-diff использует новый scope-check и только exact paths; после фактического review остаётся strict final check. Это не право пропустить native Risk/Contracts, selected support или final artifact lint.
- Первый executable Planner handoff сохраняет strict `--preflight`. Genuine refinement при materialized live review использует scope-check только для inventory вместе со всеми прежними contract/lint/machine-authority/handoff obligations. На этом пути не остаётся unconditional требования preflight-pass.
- Не меняется existing `same-contract reroute` с пропуском Planner. Semantic fingerprint exception вне `In progress` / `Ready for Review` не расширяется: такой случай остаётся штатным Architect blocker.
- Для этих callers синхронно материализуются templates, Architect inventory guidance, emitted `plan_lint.py` guidance и реальные generated/Copier consumers. Derived handoff digest остаётся derived/red и не становится новым источником разрешений.

### Review самого source-fix
Native review проходит на неизменённом accepted runtime. До первого review файла inspection разрешён только в границах current canonical bucket README и reviewer prompt: planned absence с честным expected nonzero там, где он документирован; никакого fake green. Исторические expected-red записи не создают waiver. Если materialized-red/rerun самого исправления потребует исключения, не описанного frozen runtime canon, — STOP с concrete coordinator question; candidate mode для обхода не активируется. Наблюдаемый Architect bundle — именно source-local `.tmp/role_bundles/architect.xml`, SHA256 `b800ad30672ae48745d4e6f51eb515ffc4c11f6e5048206bf0d5bb220ee8327b`; observed default/default/tooling refs относятся к нему, не к immutable baseline project. Это не доказывает candidate prompt adoption. Legacy builder читает frozen runtime corpus; ради этого наблюдения frozen runtime/bundle не регенерируется. Перед будущим Manager/Reviewer run обязателен fresh readback их фактического bundle; conflicting prompt/runtime binding — STOP координатору. Candidate flags не подставляются в frozen helper.
