# Установка Planveyor

[English](install.md) · **Русский**

Это руководство ведёт от скачивания до проверенной копии Planveyor, из которой можно создать первый sibling. Среду вы готовите сами: Planveyor ничего не устанавливает, не обновляет и не чинит. Если предпосылки не хватает, команда её называет и останавливается.

## 1. Требования

Первая версия поддерживает одну среду:

- macOS;
- Git, zsh, ripgrep (`rg`) и `make` в `PATH`; в macOS Git и `make` входят в Xcode Command Line Tools;
- активированное окружение Python 3.12 с пакетами в версиях из `requirements-dev.lock`, среди них Copier 9.18.2 и PyYAML 6.0.3.

Проверьте инструменты:

```zsh
git --version
zsh --version
rg --version
make --version
```

Windows, Linux и версии Python, кроме 3.12, первая версия не поддерживает.

## 2. Клонирование репозитория

```zsh
git clone https://github.com/planveyor/planveyor.git
cd planveyor
```

Копия может лежать в любом каталоге: фасад находит свой корень по пути к `bin/planveyor`. Перед каждой командой фасад проверяет, что `git` запускается, в копии есть метаданные Git, а `HEAD` указывает на коммит. В копии без метаданных Git, например в распакованном архиве, команда останавливается с сообщением `runtime Git preflight failed`.

Не оставляйте в копии незакоммиченных изменений и неотслеживаемых файлов: с ними `planveyor sibling init` и `upgrade` откажут.

## 3. Окружение Python

Окружению нужен Python 3.12, и оно должно оставаться активированным, пока вы работаете с Planveyor: фасад берёт первый Python 3.10–3.12, который найдёт в `PATH`, и проверяет `python3`, `python`, `python3.12`, `python3.11` и `python3.10` в этом порядке; при активированном окружении это его `python3`. Создать окружение можно любым способом, если требования выполнены.

### Пример: conda

```zsh
conda create -n planveyor python=3.12
conda activate planveyor
```

### Установка закреплённых пакетов

В активированном окружении один раз выполните из корня копии:

```zsh
make bootstrap-python
```

`make bootstrap-python` выбирает интерпретатор в таком порядке: `PYBIN`, если переменная задана, затем `python` активного conda-окружения, затем первый `python3` в `PATH`. Если версия не входит в диапазон 3.10–3.12, команда останавливается. Иначе она ставит пакеты из `requirements-dev.lock` через `pip`. Фасад `PYBIN` не читает, поэтому не задавайте эту переменную или укажите в ней то же окружение.

## 4. Как вызывать команду

Из корня копии вызывайте фасад напрямую:

```zsh
./bin/planveyor planveyor_help
```

Чтобы вызывать его как `planveyor` в текущей вкладке, добавьте копию в `PATH`, находясь в её корне:

```zsh
export PATH="$PWD/bin:$PATH"
```

Эта строка не меняет настройки оболочки, и в новой вкладке её нужно выполнить снова. Отдельный установщик команд не нужен. Не делайте на `bin/planveyor` символическую ссылку из другого каталога: через символическую ссылку фасад не запускается.

## 5. Проверка установки

```zsh
./bin/planveyor planveyor_entry_doctor
./bin/planveyor planveyor_runtime_info
./bin/planveyor planveyor_help
make verify
```

`planveyor_runtime_info` печатает корень копии Planveyor, из которой идут команды, корень проекта, вид исходников и Python, которым пользуется фасад. `planveyor_entry_doctor` ещё проверяет, что команда идёт через фасад, и печатает те же строки:

```text
runtime_root=/path/to/planveyor
project_root=/path/to/planveyor
source_state=pinned
source_kind=git
python_executable=/path/to/envs/planveyor/bin/python3.12
child_shell=planveyor-child-shell.v1
```

Проверьте, что `python_executable` указывает на окружение из шага 3. `planveyor_help` выводит список команд и показывает runner каждой роли, то есть её агентный харнес. `make verify` запускает быстрый маршрут из руководства [«Маршруты проверки»](../tools/verify_suite.ru.md): проверки целостности копии, которые только читают файлы. При успехе вывод содержит строку `VERDICT: GREEN`.

Эти проверки показывают, что фасад запускается, находит копию и Python вашего окружения, а копия проходит проверки целостности. Агентный харнес, вход в него и запуск ролей они не проверяют: всё это нужно только командам, которые запускают роли.

## 6. Среда для ролей

Для ролей есть ещё два условия. Python 3.12 должен стоять первым в `PATH` и в login shell: там Codex выполняет команды ролей, и там же обвязка стека в sibling может вызвать голый `python3`. `TMPDIR` должен указывать на существующий каталог вне любого Git-репозитория. Как проверить оба условия, сказано в разделе [«Поддерживаемая среда»](launch-and-role-modes.ru.md#поддерживаемая-среда) руководства запуска.

## 7. Агентный харнес

Роли работают в агентном харнесе. Маршрут sibling использует Codex CLI: установите его, выполните вход и настройте роли по разделу [«Настройка Codex»](launch-and-role-modes.ru.md#настройка-codex). Какой харнес использует каждый маршрут и что для него настраивается, описано на странице [«Агентные харнесы»](harnesses.ru.md).

## 8. Дальше: первый sibling

Первый sibling создайте так, как описано в [руководстве по sibling](stack-sibling.ru.md#один-раз-среда-и-создание-проекта).

Planveyor не обновляет себя сам. Обновляйте копию привычным способом и переводите sibling на новую версию по разделу [«Получить новую версию Planveyor»](stack-sibling.ru.md#получить-новую-версию-planveyor).

## Если команда остановилась

| Сообщение | Что сделать |
| --- | --- |
| `runtime Git preflight failed: category=missing_git` | Добавьте `git` в `PATH`. |
| `runtime Git preflight failed: category=missing_repo` | Работайте в клоне Git из шага 2. |
| `ripgrep (rg) is required` или `zsh is required` | Добавьте названный инструмент в `PATH`. |
| `no Python 3.10-3.12 found on PATH` | Активируйте окружение из шага 3. |
| `Missing Copier 9.18.2`, `Copier 9.18.2 is required` или `Missing PyYAML` | Выполните `make bootstrap-python` в активированном окружении. |
| `Выбранный runtime содержит незакоммиченные изменения` | Закоммитьте изменения и неотслеживаемые файлы копии Planveyor или перенесите их из неё. |

После исправления повторите ту же команду.
