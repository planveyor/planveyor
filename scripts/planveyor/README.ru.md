# `scripts/planveyor/`

[English](README.md) · **Русский**

Слой модулей для `scripts/planveyor.zsh`. Начальную загрузку (bootstrap) ведёт фасад. Он решает, какой модуль загрузить немедленно (eager), какой по требованию (lazy), а какой по условию (conditional). Напрямую эти файлы не запускают.

## Опись модулей движка

Фасад (не модуль): `scripts/planveyor.zsh`.

| Модуль | Режим загрузки | Граница |
| --- | --- | --- |
| `contract_authority.zsh` | немедленно, как зависимость начальной загрузки | компонент полномочий; работает до вызова публичных обёрток |
| `session_init.zsh` | немедленно | вспомогательные функции инициализации для артефактов, ID сессий и новых сессий ролей |
| `role_runtime.zsh` | немедленно | точки входа ролей и Manager, которые действуют по статусу плана |
| `docs_finalize.zsh` | немедленно | обёртки слоя, который переносит память агента в документы и закрывает их (memory-finalize/doc-closeout) |
| `home_runtime.zsh` | по требованию | адаптер для Codex home пользователя: выдаёт отчёт или отказ |
| `provider_runtime.zsh` | по условию | выбор провайдера и его происхождения (provenance) |

## Порядок немедленной загрузки

1. `session_init.zsh`
2. `role_runtime.zsh`
3. `docs_finalize.zsh`

## Правила

- Новые команды для пользователя должны начинаться с префикса `planveyor_`.
- Модуль не должен зависеть от файлов, которые загружаются позже него.
- Не добавляйте личные пути владельца, запасной путь через домашний каталог, переопределение корня и запасной путь через прослойку (shim) в репозитории. Физический корень копии Planveyor определяет загруженный скрипт Planveyor. Внешний проект выбирают только префиксом фасада `--project /absolute/path/to/consumer`. Состояние копии Planveyor и необязательный `PLANVEYOR_CODEX_HOME` задаются явно, вне дерева продукта.
- Если меняется порядок загрузки или граница между модулями, обновите комментарий в `scripts/planveyor.zsh` и этот README.
