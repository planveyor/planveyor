# `scripts/`

[English](README.md) · **Русский**

Общая опись скриптов в `planveyor`.
Постоянное правило: файл не считается мёртвым только потому, что его не загружает `scripts/planveyor.zsh`.

## Классы точек входа

- `wrapper entrypoint`: команда shell или прослойка (shim) для пользователя, доступная через `scripts/planveyor.zsh` или через shell-обёртку из репозитория.
- `python CLI`: исполняемый скрипт на Python с контрактом командной строки, в том числе утилиты только для оператора.
- `import-only helper`: модуль Python, который использует другой скрипт или тест. Напрямую его обычно не запускают.
- `test carrier`: регрессионные тесты `scripts/test_*.py` для семейства скриптов или вспомогательных скриптов.
  Каждый такой файл тестов должен запускаться и отдельно, из корня репозитория:
  `"$PYBIN" -B scripts/test_<name>.py`, если план называет эту линию.
- `historical/deprecated`: скрипт оставлен ради старых планов, ревью, адресных пакетов, заметок о совместимости или узкой проверки на совпадение поведения.
- `candidate for removal`: после ограниченного поиска по репозиторию, документам и тестам у скрипта не осталось действующих потребителей. Для удаления всё равно нужна отдельная отложенная задача или дочерний план.

## Правила описи

- Поиск должен охватывать `scripts`, `docs`, `Makefile` и `.github`, а не только `scripts/planveyor.zsh`.
- До любого решения об удалении исторические ссылки записывают отдельно от действующих потребителей.
- CLI только для оператора может обходиться без обёртки, если контракт команды описан.
- Удаление скриптов, новые обёртки, генераторы описи и изменения поведения не входят в срез, который только составляет опись, если дочерний план не решил иначе.
- Если скрипт когда-нибудь отнесут к `candidate for removal`, создайте или обновите строку отложенной задачи с `plan=null`. Она остаётся такой, пока задачу не продвинут в план удаления.

## Виды доказательств

- `wrapper`: прямой вызов из shell-обёртки или из `planveyor.zsh`.
- `test`: тест `scripts/test_*.py` напрямую импортирует или запускает скрипт.
- `docs`: действующее руководство, плейбук или документ процесса велит оператору пользоваться скриптом.
- `helper`: другой скрипт из репозитория напрямую импортирует или вызывает его.
- `historical`: старые планы, ревью и адресные пакеты объясняют происхождение, но сами действующими потребителями не считаются.

## Слой модулей

Навигацию по внутренним модулям `scripts/planveyor.zsh` ведёт `scripts/planveyor/README.ru.md`.
Когда слой модулей меняется, держите этот файл в согласии с действующим списком модулей `scripts/planveyor/*.zsh` и порядком загрузки через `_planveyor_source_module`.
